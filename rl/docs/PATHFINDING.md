# 静态寻路表示选型：NavMesh vs 路点图（+ 学习式关键点）

> 约束（来自你的设定）：**地图静态**、动态部分交给 RL；**不引入动态重建**；场地是 200×200 平面 + 轴对齐 `BoxShape3D` 墙（1 m 厚长墙 + 20 m 墙），当前 6 种变体 + 多场地，全部手工搭好。

---

## 1. 结论

**推荐：路点图（由墙盒子自动生成，带障碍膨胀的可见性图风格）。**
**NavMesh 作为备选**，触发条件只有一个——几何变复杂（斜墙、坡道、多层、程序化生成的随机地图）。

**决定性理由有三条**（后两条是 NavMesh 在这个项目里的实际风险，不是理论偏好）：

1. **接口天然对齐**：路点图的节点**本身就是**你准备喂给 RL 的 lookahead 路点，不需要每步再从导航服务器里"抽折线"；NavMesh 要多一步路径抽取 + string pulling。
2. **薄墙与窄道风险**：NavMesh 是体素化烘焙，受 `cell_size` / `agent_radius` 影响。你的墙只有 **1 m 厚**，而车宽约 2 m（膨胀半车宽后 3 m）——**在墙场景那条窄道里，参数稍大就会把通道烘没或漏墙**。这是你已经在墙场景踩过的痛点（20 m 墙横在唯一通道上）。路点图用显式几何检查建边，**没有这个失效模式**。
3. **可复现性**：NavMesh 是烘焙产物，烘焙参数不同 → 路径不同 → **训练与评估之间出现隐性分布漂移**，直接违反你已经建立的"训练/评估/演示同配置"纪律。路点图是纯数据（节点 + 边），可 diff、可版本化、可断言。

---

## 2. 逐项对比（针对你的场地）

| 维度 | NavMesh | 路点图（自动生成） |
|---|---|---|
| 生成成本 | 低（引擎烘焙，0 代码） | 低（约 80–120 行：AABB 涂格 → 取凸角点 → 可见性建边） |
| 几何复杂度适应 | **强**（斜墙/坡道/多层） | 弱（斜墙要额外处理；你的场地全是轴对齐，够用） |
| 路径最优性 | 好（贴角，但需 string pulling + 曲率平滑） | **接近最优**：多边形障碍下最短路顶点必在障碍凸顶点上（可见性图性质） |
| 薄墙 / 窄道 | **有失效风险**（体素化 + agent_radius） | 无（建边时显式做障碍膨胀与碰撞检查） |
| 可复现性 | 依赖烘焙参数，需版本化烘焙资源 | 纯数据，完全确定 |
| 给 RL 的接口 | 需每步抽折线 → 再选 lookahead | **节点即路点**，直接取即可 |
| 动态障碍 | `NavigationObstacle3D` 的 avoidance 模式不重建地图（可用）；carving 模式会改地图（**不要用**） | 完全不动地图，动态全交 RL（符合你的约束） |
| 引擎支持 | 原生（`NavigationServer3D` + `NavigationAgent3D`） | 原生（`AStar3D` / `AStarGrid2D`） |
| 调试性 | 黑盒（烘焙结果难读） | 好（图可画、可断言、可单测） |
| 程序化/随机地图 | 强 | 需自动生成器（这正是"学习式关键点"的用武之地） |
| 多目标（多乘客） | 每目标一次路径查询 | 同上；但节点少 → 查询更便宜 |

## 3. 路点图的一个额外大收益：给调度器提供**精确距离**（建议立刻用上）

静态图建好后，节点数只有几十个 → **Floyd–Warshall 全源最短路瞬间算完**，于是：

```
dist(车 i → 乘客 j) ≈ d(车 i 最近的节点, 乘客 j 最近的节点) + 两端接入段
```

**O(1) 查表**。这意味着你在 `MARL_DESIGN.md` 里那个"配对分数矩阵"可以直接用**精确路径距离**（甚至精确路径长度作为特征），而不是欧氏距离近似——**在墙场景里欧氏距离会严重误导调度**（隔一堵墙 5 m，实际要绕 40 m）。

一句话：**静态图顺便把调度器的代价矩阵变成了精确的、免费的。** 这件事的性价比比"选 NavMesh 还是路点图"本身还高。

## 4. 学习式关键点放置：怎么定位才站得住

你的直觉有价值，但**必须先接受一个理论天花板**：

> 在**多边形障碍**环境下，最短路径的折点必然落在障碍的**凸顶点**上（可见性图的最优性）。你的墙全是多边形（盒子），所以"障碍凸顶点集"本质上**已经是最优节点集**。

因此——

- ❌ 定位成"学出来的关键点能给出更短路径" → **理论上是错的**，一定输给解析可见性图；
- ✅ 定位成 **"在固定节点预算下逼近最优"** 与 **"适应程序化/新地图"**：
  - 节点越少 → 图越小 → A* 扩展节点越少 → 查询越快 → **给 RL 的路点引导也更简洁**；
  - 目标是"K=8 个节点的学习式布点，路径长度落在最优的 X% 以内；而均匀采样要 K=40 才能达到同样水平"。

**这是唯一站得住的比较维度，而且它是可量化的帕累托曲线（节点数 vs 路径长度）。**

### 训练方式（很便宜，而且**不需要车辆仿真**）

关键洞察：**关键点放置可以完全离线训练，与驾驶 RL 解耦。**

```
① 候选点：把自由空间粗网格化（如 1 m，得到几百个候选）
② 打分网络：输入候选点的局部几何特征（到最近障碍距离、可见性统计、到起终点的距离分布）
   → 输出分数 → 取 top-K
③ 评估：用这 K 个节点建可见性边 → 在采样的 (起点, 终点) 对上跑 A* → 路径长度
④ 奖励：−平均路径长度（相对最优可见性图的比值）
⑤ 训练：REINFORCE / 进化策略，几分钟级
```

**它不依赖物理仿真、不依赖 PPO、不与驾驶策略耦合**——一个自包含的小实验，适合作为方法论亮点，也适合在超算上大并行。

### 我更推荐的两个更稳的替代（同样有"学习"含量，但更容易训）

1. **学习式点/边剪枝**：从完整可见性图出发，学一个二进制掩码决定丢哪些节点/边，损失 = 路径长度劣化。有监督信号、训练稳定，直接产出更小的静态图。
2. **学习式边权（拥塞代价）**：图保持静态（符合你的约束），学出来的是**每条边在什么情况下"贵"**（拥堵、被抢客风险、对手密度）。这是"静态地图 + 动态决策"的最自然形态，而且**与调度器共用同一套学习信号**。

## 5. 对照实验设计（四档表示 + 帕累托曲线）

| 编号 | 表示 | 说明 |
|---|---|---|
| G1 | 均匀网格图（1 m） | 下界参考：节点多、路径好、查询慢 |
| G2 | 均匀随机采样图（同节点数） | 公平的随机基线 |
| G3 | **解析可见性图（障碍凸顶点）** | **上界参考**（近乎最优） |
| G4 | **学习式布点（同节点数）** | 待验证 |

**指标**：
- **帕累托曲线**：节点数 → 平均路径长度 / 最优路径长度（相对 G3）；
- 查询成本：A* 扩展节点数、单次查询耗时；
- 覆盖率：随机 (起点, 终点) 对中"无解"或"路径 > 2× 最优"的比例；
- 端到端（接上 RL 后）：成功率、平均到达时间。

**判定**：G4 若在**节点数相同**时优于 G1/G2，且在**节点数 1/4** 时仍能落在 G3 的 5–10% 以内 → 结论成立（"稀疏但接近最优"）。若不能，就诚实报告"解析可见性图已经足够，学习式布点在此几何下无收益"——**这也是有价值的负结果**，而且省时间。

---

## 6. 实现顺序（建议）

1. **先实现 G3（解析可见性图 / 或"墙盒子凸角点 + 可见性建边"）**：它是产品版，也是所有比较的上界。
2. **建全源最短路表**，把调度器的配对代价换成精确路径距离（立刻受益）。
3. **接 A* 路点进 RL 观测**（`NAVIGATION.md` 的 10 维引导），势函数改沿路径弧长。
4. **再做 G1/G2/G4 的比较**：纯粹作为方法论章节，不与主线耦合。
5. NavMesh 只在"地图出现斜墙/坡道/程序化生成"时再启用，届时用它替代 G3 的位置。

## 7. 关键点网络：有记忆还是无记忆

### 结论：**无记忆（前馈），而且"有记忆 vs 无记忆"其实是个伪二选一**

先拆开两个被混在一起的概念：

| | 时间记忆（RNN/GRU/LSTM 隐藏状态） | 递增构造的状态（已选点集合） |
|---|---|---|
| 解决什么 | **部分可观测**（POMDP）、跨时间的信用分配 | 一次性决策变成 K 次决策（自回归） |
| 你需要吗 | **不需要**：地图是静态且完全观测的 | 可选；但不需要循环权重，把"已选"当**输入**即可 |

**关键点放置是"给定完整静态地图，输出一组点"，没有任何时间维度、没有部分可观测性。** 记忆在这里没有可做的事——它唯一有用的场景是"地图逐步揭示"（探索/传感受限建图），那不是你的问题。

### 推荐形式：一次性给所有候选打分 → top-K（不是自回归）

```
候选点（粗网格自由格，几百个）
   ↓ 局部几何特征（到最近障碍距离、可见性统计…）
   ↓ ┐
     ├─ 全局上下文：对全部候选做池化/注意力 → 一个 context 向量
   ↓ ┘
score(候选 i) = MLP(局部特征_i , context)        ← 一次前向，全并行
   ↓ top-K → 建可见性边 → 静态图
```

三点好处：
1. **一次前向、完全并行**，比 K 次自回归快 K 倍——你猜的"无记忆更快"是对的，但原因不是"记忆慢"，而是**避免 K 次串行**；
2. **置换不变**，与候选顺序无关；
3. **可复用**：这个"带全局上下文的逐候选打分"模块，跟调度器的"车 × 乘客配对打分"、炮台的"炮台 × 敌人目标打分"是**同一个结构**。**写一次，用三处。**

注意：这里的 `context` **不是隐藏状态**，它是当前输入的一部分（类似 CLS token / attention pooling）。"无记忆"指的是**没有跨时间的隐藏状态**，不是"不看全局"。

### 训练：你的思路完全可行，而且推荐**监督模仿**而非 RL

> 随机生成地图与状态 → 和专家算法比较。

这正是**行为克隆（BC）**，而且在这个问题上比 RL 好：

1. **你有近乎最优的教师**（多边形障碍下的可见性图 = 最优节点集），没有理由用 RL 从零摸索；
2. **避开子集选择的信用分配问题**：top-K 之后"该怪哪个点"是组合爆炸的，BC 用逐候选标签直接绕开；
3. **数据集生成完全离线、不依赖车辆仿真**，可无限并行。

**标签怎么造（比"使用频率"更好的做法）**：
```
① 用凸角点集 V 建完整可见性图，跑全源最短路（|V|≈30 时 Floyd–Warshall 瞬间完成）
② 对每个顶点 v：算"删掉 v 之后平均最短路长度的劣化量"（leave-one-out 边际贡献）
③ 归一化成连续分数 → 作为回归标签（比二分类好：它给了分级的重要性）
④ top-K 时按预测分数排序
```
> 备选（更便宜但更粗）：在随机 (起点, 终点) 对上统计每个顶点的**最短路径经过频率**，归一化当标签。

**为什么用回归而不是二分类**：频率/边际贡献是**分级**信息，top-K 本质是排序操作，回归标签直接对齐排序目标。

### 数据集的三个坑

1. **地图必须程序化大量随机生成**（随机数量/尺寸/位置的轴对齐矩形，并保证连通）。你现在只有 6 种变体，网络会直接背下来；**必须留出没见过的地图做测试**；
2. **K 与 |V| 的关系**：若 K ≥ |V|，任务退化成"把专家点全拿上"，没有学习价值。**只有 K < |V| 的预算受限区间才有意义**（这也是唯一能站住的比较维度）；
3. **候选集要包含非角点的自由空间格点**：否则网络学的是"重新发现角点"（一个可以手算的东西）；包含自由格点后才能体现"预算受限下如何取舍"。

### 如果一定要优化真实目标（路径长度）而不是模仿教师

用**可微软 top-K**（soft top-K / Gumbel top-K）替代硬选择，让 `路径长度` 的损失直接回传到每个候选的分数上——**端到端、不需要教师**。
代价：软选择与硬选择之间有偏差，需要退火。作为 BC 之后的微调手段即可，不必作为主线。

---

## 8. 一句话总结

**用自动生成的路点图（可见性图风格，节点落在墙的凸角点）——它天然就是喂给 RL 的路点、没有薄墙烘焙风险、完全可复现，而且顺便给调度器提供了精确路径距离；NavMesh 留给几何变复杂的时候。学习式关键点不要定位成"更短路径"（理论上赢不了可见性图），要定位成"固定节点预算下逼近最优 + 适应程序化地图"，并把它做成一个**离线、不依赖驾驶仿真**的小实验。**
