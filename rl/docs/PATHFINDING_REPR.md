# 寻路表示选型：NavMesh vs Waypoint Graph（+ 学习式关键点放置）

> 你的地图实况：**200×200 m 平面、轴对齐 `BoxShape3D` 墙（1 m 厚长墙 + 一堵 20 m 墙）、完全静态**，车宽约 2 m、非完整约束（最小转弯半径）、可倒车。
> 目标用途：为 RL 引导层提供 3–5 个 lookahead 路点。

---

## 1. 结论先行

| 场景 | 选它 | 理由 |
|---|---|---|
| **默认选择** | **NavMesh（`NavigationRegion3D`，烘焙时设 `agent_radius`）** | 0 行代码、**角落膨胀由引擎正确完成**（这是它相对栅格的最大真实优势）、静态几何正合适 |
| 需要**确定性/可复现**或将来**动态封路**（炮台打坏路、临时障碍） | **`AStarGrid2D`（0.5 m 栅格 + 半车宽膨胀）** | 完全确定、可复现、封路是 O(1) 改一格；烘焙结果可能随版本/平台变化，会破坏你"同场景同结果"的纪律 |
| 想要**类人行驶轨迹**（走车道中间而不是贴角最短） | Waypoint Graph | 折线路径天然更"像人开的"，但**手工放置不可扩展**（6 种变体 + 未来地图）→ 必须自动生成 |
| **研究分支**（你要做的比较） | 学习式关键点放置 | 见第 4–8 节：**能打平就已经不错，真正的机会在"任务感知放置"** |

**一句话**：在你的地图上，NavMesh 与栅格 A* 都是"够用且便宜"的选择，**寻路表示不是瓶颈，路径形状（曲率可行性）才是**。

---

## 2. 逐维度比较

| 维度 | NavMesh | Waypoint Graph | 对你的权重 |
|---|---|---|---|
| 几何表达 | 凸多边形拼接，天然贴合复杂地形 | 离散关键点 + 邻接边 | 你的地图简单 → 两者都够；NavMesh 的表达力用不上 |
| **障碍膨胀（车宽）** | ✅ 烘焙时 `agent_radius` **正确腐蚀可走区域（含角落）** | ❌ 需要自己保证边的净空；放错点的边会切墙角 | **高**——这是 NavMesh 唯一真正拉开差距的地方 |
| 路径长度 | 漏斗算法给出走廊内最短路径 | 依赖节点密度；稀疏则明显变长 | 中 |
| **路径形状（车能不能开）** | 最短路径**贴角**，转角曲率往往超出最小转弯半径 → **两者都必须再做曲率受限平滑** | 折线转角较缓，天然更接近车的可执行轨迹 | **高** |
| 查询成本 | 多边形 A*，几十个节点，微秒级 | 节点数十个，最快 | 低——查询是低频的（目标变化/卡死才查），不是瓶颈 |
| **确定性/可复现** | ⚠️ 烘焙参数 + 平台差异可能带来非确定性 | 生成后可复现 | **高**——你现在的评测纪律要求"同场景同结果" |
| 动态变化 | 墙变要重烘（贵）；乘客/目的地变**不影响** | 图不变；但要处理"车/目标不在节点上"的最近点接入 | 中（墙静态，乘客动态 → 两者都满足） |
| **运行时封路/破坏** | 重烘，贵 | 删边，便宜 | 中——炮台阶段可能出现 |
| 手工成本 | 0（编辑器烘焙） | **高**（手工放置不可扩展） | 高 |
| 自动生成 | 内建 | 需自己实现（栅格采样/中轴/随机采样+净空筛选） | 高 |
| 调试可视化 | 编辑器内建 ✅ 出论文图好看 | 需自己画点与边 | 低 |
| 与 RL 引导的耦合 | 输出折线 → 取 lookahead | 同 | 低 |

**归纳三条决定性事实**
1. **膨胀**：NavMesh 帮你把车宽算对了；栅格方案要自己涂格子（能近似做到）；路点图最容易出错。
2. **确定性**：追求可复现评测 → 栅格最稳；NavMesh 需要把烘焙固化成资源文件并纳入版本控制。
3. **形状**：无论选哪个，**你都需要一层曲率受限的路径平滑**（样条 / Dubins / Reeds-Shepp），否则贴角路径交给非完整约束的车就是不可行指令——这正好又是攻击面 C 的"指令不可行率"来源。

---

## 3. Waypoint Graph 的真正问题不是"好坏"，是"谁放点"

手工放置 **6 种场地变体 + 未来地图**不可维护，所以只有两条路：

- **自动生成**：均匀栅格采样 / 中轴（medial axis）/ 泊松盘采样 + 净空筛选 / 墙角+门口关键点。这**本身就是算法设计**，一旦你开始调"放点的规则"，就已经在做"学习式放置"想做的事了；
- **学习式放置**：你想比较的那个版本。

---

## 4. 学习式关键点放置：先看清信号从哪来

你的隐含目标是"端到端训练一个网络放点，让任务表现更好"。**这条路的核心风险是信用分配链太长**：

```
点的位置 → 图结构 → A* 路径 → 平滑后的可执行轨迹 → RL 动作 → 任务回报
```

回报经过 5 层非微分变换才影响到"点放在哪"，**稀疏、高方差、极低样本效率**。直接用它做 RL 目标，很可能训练不出来，或者要好几个数量级的数据。

**所以第一步不是选网络，而是选训练信号。** 四种可行形式（按推荐度排序）：

| 形式 | 做什么 | 信号 | 评价 |
|---|---|---|---|
| **(b) 学打分 + 经典选择**（推荐） | 生成候选点集（栅格/随机采样），小网络对每个候选**打分**（特征：净空距离、到最近节点距离、可视邻居数、走廊宽度、局部几何），再用贪心/子模最大化选出 K 个 | **稠密**：每个候选点一个标签（来自经典生成器或覆盖率目标） | 与你调度器"学分数 + 经典匹配"**架构一致**；训练稳定、可解释、能控制 K |
| (a) 模仿经典生成器 | 用中轴/净空采样生成专家点集，网络模仿 | 稠密监督 | 最容易训，但要回答"比经典好在哪"，否则只是蒸馏 |
| (c) 直接回归点坐标（集合预测） | 输出 K 个坐标，用**几何目标**（覆盖率 + 连通性 + 净空）训练 | 可微几何损失 | 可行（像 DETR 的集合预测），代码量中等；但目标是几何的，不是任务的 |
| (d) RL 直接搜放置 | 回报用**几何代理**（覆盖率、路径长度比），不是任务成功率 | 稠密代理 | 比用任务回报可行得多；但仍是元层优化，慢 |

**关键判断**：如果训练信号最终来自"几何覆盖率/净空/连通"，那你其实是在**重新发明中轴采样**——一个设计良好的经典采样器会打平你。只有当目标是**任务分布相关**的时候，学习才有不可替代的空间（见第 8 节）。

## 5. 基线与指标（比较必须这样做才成立）

**五个基线**
1. 均匀栅格（匹配相同节点数 K）——最公平的"同等预算"对照；
2. **中轴/净空采样**——经典强基线（最可能打平你的那个）；
3. 墙角 + 门口关键点（"人类直觉"基线）；
4. 泊松盘采样；
5. 随机放置（弱基线，用于证明"确实学到了东西"）。

**指标**
- **成本**：节点数 K、边数、查询时间；
- **几何质量**：平均路径长度 / 栅格 A* 最优长度的比值（最优性差距）、自由空间覆盖率（距最近节点 ≤ X m 的比例）、**平滑后轨迹的净空违规率**（这条最容易被忽略、也最致命）；
- **下游任务**：送达成功率（带判据）、平均到达时间、卡死率；
- **泛化**：在**没见过的地图**上的同一组指标（这是学习版唯一可能稳定赢的地方）。

**诚实预期**：在你这几张简单地图上，**【学习的放置 + 经典选择】大概率只能与【中轴/净空采样】打平**。把"打平"当作可接受结果，把胜负点押在泛化或任务感知上（第 8 节），否则这个分支会吞掉你大量时间。

---

## 6. 为什么要保持"确定性可复现"

你的评测纪律是"同场景、同判据、同种子 → 结果可比"。学习式放置引入了一个新变量：**同一张地图，不同模型权重会给出不同的图**，于是"换了策略以后变好/变坏"就无法归因。

**对策**：把放置网络**冻结并版本化**（和场景文件一起进 git），评测时只比对"固定图 + 不同策略"，比较放置方案时只比对"固定策略 + 不同图"。**永远不要让两个变量同时动。**

---

## 7. 顺带一个便宜的替代：不要图，直接采样

如果目的只是"给 RL 提供引导"，有一个比任何图都便宜的方案：**在自由空间里撒一批候选点，用可见性/净空连边，只保留引导所需的那条走廊**。对 200×200、几堵墙的地图，代码量与栅格 A* 相当，但节点数少一个数量级。可以作为"极简路点图"基线。

---

## 8. 真正值得做的研究角度：任务感知放置（而不是几何最优放置）

这是我认为唯一能让"学习式放置"讲出不可替代价值的方向：

- 经典采样器（中轴/净空/均匀）优化的是**几何覆盖**——它假设"每个位置同等重要"；
- 但你的任务有**明确的非均匀分布**：乘客出现在哪里、目的地分布在哪、哪些路口是争夺点。**为均匀覆盖优化的点集，在任务分布上往往是次优的**；
- 于是目标改成：**在乘客/目的地分布加权的意义下最小化期望路径长度**，节点预算固定为 K。这时的最优解**依赖任务分布**，而任务分布是可以学、也可以随训练数据更新的——**经典几何采样器在原理上无法表达这个目标**。

这与你在避让那一层的立论方式完全同构：**不是"我们比经典更会算几何"，而是"经典的目标函数里没有任务"**。

**具体实验**：固定 K（比如 20 个节点），比较
① 均匀栅格、② 中轴采样、③ 学习放置（几何目标）、④ **学习放置（任务加权目标）**，
指标用**任务加权的平均路径长度、平均接客时间、送达成功率**。
预期：①②③ 彼此接近，**④ 在任务指标上明显更好**。这张表就是这条线的核心结果。

---

## 9. 决策建议

1. **主链路**：NavMesh（烘焙成资源、纳入版本控制）**或** `AStarGrid2D`（0.5 m + 半车宽膨胀，确定性强）。两者都比路点图省事，先用起来；
2. **无论选哪个，都要加曲率受限平滑**——否则路径交给非完整约束的车依然是不可行指令；
3. **路点图作为研究分支**，且直接走 **(b) 学打分 + 经典选择**，不要用任务回报端到端训放置；
4. 这个分支的胜负点押在 **④ 任务感知放置** 上，而不是"几何上比中轴采样更优"；
5. 放置网络**冻结 + 版本化**，评测时一次只动一个变量。
