# 交接提示词：实现 Informed RRT* 全局规划层

> 用法：新开一个对话，把下面整段（含代码块内的内容）粘贴进去。

---

为 Godot 车辆仿真项目实现基于 **Informed RRT\*** 的全局路径规划层。仓库里已有相关设计文档可先读：`rl/docs/NAVIGATION.md`（第 8 节是本次任务的成立性审计）、`rl/docs/PATHFINDING.md`、`rl/docs/WAYPOINT_HOWTO.md`、`rl/docs/PLAN_v2.md`。

## 项目背景

- Godot 4.7.1 + 强化学习（Stable-Baselines3 PPO，经 godot_rl 0.8.0 插件用 TCP/JSON 在 `127.0.0.1:11008` 通信，Godot 侧是 `TaxiSync extends Sync`）。
- 任务：自动驾驶出租车接送乘客。已有成果（均带判据）：单车空场地成功率 1.00（判据：接客 3 m / 送达 4 m / 停稳 2.5 m/s）、障碍场地 0.965、六种场地变体混合 0.44–0.60、多车竞争（4 场地 × 4 车、2 阵营、32 个并行智能体、严格判据 2/2.5/1.5）0.105。
- 车辆有真实动力学（发动机 / 变速箱 / **扭矩转换器** / 转向），车宽约 **2 m**；物理 tick **240 Hz**，**1 决策步 = 8 物理帧**（每帧 1/60 s 仿真时间），回合上限 1350 步 = 180 s。
- 场地：**200×200 m 平面 + 静态轴对齐 `BoxShape3D` 墙**（1 m 厚、50 m 高、最长 200 m，另有一堵 20×20×1 的墙），墙与场地都在 `.tscn` 里手工摆放，**静态不变**。
- 观测 419 维 = 8 自车状态 + 384 射线 + 27 相对位置；动作 3 维（油门 / 转向 / 倒车，**无独立刹车**）。
- 工程纪律：成功率必须带判据与阵营数 / 智能体数；**奖励值不作为验收标准**（用业务指标）；改场景参数后必须重启场景；训练 / 评估 / 演示必须同配置同步长。

## 已确定的架构（不要重新论证）

三层：**① 全局规划层（本次任务）→ ② 引导表示层（把路径变成 RL 观测）→ ③ 局部控制层（RL：动态避让、动力学、停稳精度、倒车脱困）**。

- **事件触发重规划**：接客 / 送达 / 目的地变更时规划一次。不是每物理帧，也不是"烘一次永不变"。
- **路径只作参考，允许偏离**：奖励 = 沿路径弧长进度 − 横向偏差（**带死区**，如 |e| < 1.5 m 不罚）− 航向偏差；**避障优先级必须高于贴合路径**。
- **规划器做成可替换接口**（`GridAStarPlanner` / `InformedRRTStarPlanner` / `HybridPlanner`），本对话只实现 RRT 这一个，这样 RRT\* vs A\* 将来可以作为对照实验。
- 规划在 **Godot 侧（GDScript）**做；路径的 lookahead 特征作为观测发给 Python。**不要在 Python 训练循环里做规划。**

## RRT 实现要求（已讨论确定，不要重新论证）

1. 增长规则必须是：**采样 → 最近邻 → 朝采样点走一步 `step_size` → 边碰撞检查 → 入树**。**不允许"随机游走"**（既无概率完备性也判断不了何时到达）。
2. 边检查必须用**形状扫掠**（`PhysicsDirectSpaceState3D.cast_motion()` + 车的碰撞形状），**不要用单根射线**。理由：射线没有宽度；且 Godot 的 `intersect_ray` 默认 `hit_from_inside = false`，起点在墙体内部时不命中，会给出假阳性。形状扫掠自带车宽，因此**不需要手工膨胀障碍物**。
3. 树用**纯数据**（`PackedVector2Array` 位置 + `PackedInt32Array` 父指针 + `PackedFloat32Array` 成本），**不要给每个采样点生成 `Node3D` / `RayCast3D`**；可视化用 `ImmediateMesh`。
4. **回溯 = 沿 parent 指针从目标节点走回根再反转**（与 A\* 的 `came_from` 同机制）；RRT\* 的重连只改 `parent[i]`，重建代码不变。
5. 到达判定优先用**"能直连目标就直接挂上并结束"**，比"进入阈值圈"收敛快得多。
6. **固定种子**（`rng.seed = hash(task_id)`），保证同一任务重复查询得到同一条路径（保护"训练/评估同配置"纪律）。
7. **迭代预算失败必须兜底**（回退直线或网格 A\*），否则车会表现为"突然没有目标"。
8. 采样用 **goal bias（约 10% 直接采目标）**；进入 RRT\* 阶段再加 **Informed 椭圆采样**（焦点为起点与目标，`c_min` = 两点直线距离，`a = c_best/2`，`b = √(c_best² − c_min²)/2`）。
9. 规划平面是 **XZ**（Godot 3D 的水平面），探针高度固定；**不要做 3D 随机游走**。
10. 性能预期：GDScript 版 RRT\* 可能比引擎内置 `AStarGrid2D`（C++）慢数百倍。事件触发下一次查询花 50–200 ms 通常可接受，但**必须先实测**；必要时降预算或退回网格 A\*。

## 路径后处理（躲不掉，必须做）

1. **曲率平滑**（满足最小转弯半径，原始 RRT 路径是带随机抖动的折线）；
2. **净空检查**（离墙 ≥ 车半宽，用**断言**而非目测）；
3. **等间距重采样**（约 6 m）+ **lookahead 选取**（前方 3 个点喂给 RL）。

## 重规划触发条件（必须定死"偏离后是重规划还是回路径"）

任务事件 / **偏离超阈值** / **卡死检测**（N 步内沿弧长进度 < 阈值）/ 环境变化。**禁止每决策步重规划。**

## 本对话要交付的东西

1. 可运行的 GDScript 实现：`NavPlanner` 接口 + `InformedRRTStarPlanner`（含采样、最近邻、steer、形状扫掠边检查、选父、重连、到达判定、**回溯**、兜底）；
2. `goal bias` / `step_size` / 迭代预算 / 重连半径的参数选择建议与依据；
3. 形状扫掠的具体写法（碰撞层与掩码怎么设、探针高度、车形状用 Box 还是 Capsule、怎样排除车自身与乘客）；
4. 曲率平滑的实现方式（圆角 / 贝塞尔 / Reeds-Shepp 片段）与最小转弯半径从车辆参数怎么取；
5. 单测与可视化：连通性（200 组随机自由 (起点,终点)）、路径长度 / 直线距离、**净空断言**、单次查询耗时；`ImmediateMesh` 调试绘制（节点 / 边 / 路径三层，一个 `debug_draw` 开关）；
6. 与 RL 观测的接线：10 维引导的具体定义（3 个 lookahead 路点的车体坐标 6 维 + 横向偏差 1 + 航向偏差 1 + 沿路径投影速度 1 + 路点进度 1）；
7. 评估方案：**纯 RL（无路径）vs RL + 参考路径**的 A/B（成功率、平均到达时间、卡死率），以及 RRT\* 迭代预算 100 vs 1000 对策略是否敏感的消融；
8. 是否需要升维到 `(x, z, θ)` + Dubins/RS —— **先做 2D 版把链路跑通**，再根据"路径是否可跟随"决定。
