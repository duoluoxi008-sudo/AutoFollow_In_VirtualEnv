# 路点（Waypoint）算法怎么做：从零到接进 RL

> 面向"完全没做过"的情况。**核心认知：路点图 = 点集 + 边集 + 图搜索 + 路径拉直**，四件事，没有更多。
> 代码是骨架/伪码（贴近 GDScript），需要你按自己场景结构填细节。

---

## 0. 先破除三个混淆

**混淆一：以为"路点图"是个高深东西。**
它就是一个数组 `points[]` 加一个邻接关系 `edges[]`，然后用 A* 在上面找路。**"路点图"和"栅格地图"没有本质区别**——栅格只是"节点摆成点阵、边连 8 邻域"的路点图。区别只在**节点密度**和**边怎么建**。

**混淆二：把三个层次当成一个东西。**

| 层次 | 是什么 | 生命周期 |
|---|---|---|
| ① 静态导航图 | 点 + 边（房子结构） | 场景加载时烘一次，之后只读 |
| ② 路径 | A* 在①上查出的折线（从车到目标） | 目标变化/卡死时重算 |
| ③ lookahead 路点 | 从②上按固定间距取的 2–3 个点，**这才是喂给 RL 的观测** | 每个决策步更新 |

**混淆三：以为要给 RL 喂整条路径。**
不。RL 只需要"前方 6–12 m、12–18 m 左右的位置"。整条路径是你自己用的，不是网络输入。

## 1. 最小可跑版本：栅格 + A* + 拉直（约 120 行，先把这个跑通）

你不需要写 A*——Godot 4 内置 `AStarGrid2D`（栅格）和 `AStar2D`（稀疏点图）。

### 步骤 1：从场景抽出障碍（一次性）

```gdscript
# 遍历场地里的墙（你的墙是 StaticBody3D + BoxShape3D）
# 取每个墙在 XZ 平面上的 AABB，形成一个 Rect2 列表
func collect_walls(arena_root: Node3D) -> Array[Rect2]:
    var out: Array[Rect2] = []
    for body in arena_root.get_children():
        if body is StaticBody3D and body.name.begins_with("Wall"):
            var cs: CollisionShape3D = body.get_node("CollisionShape3D")
            var box: BoxShape3D = cs.shape
            var center := body.global_position          # 注意：取 XZ
            var half := Vector2(box.size.x, box.size.z) * 0.5
            out.append(Rect2(Vector2(center.x, center.z) - half, half * 2.0))
    return out
```

### 步骤 2：膨胀障碍（**最容易漏、后果最严重的一步**）

车不是一个点。把每个障碍按 `车半宽 + 余量` 向外扩：

```gdscript
var r := car_half_width + safety_margin      # 例如 1.0 + 0.5 = 1.5 m
inflated.append(Rect2(w.position - Vector2(r, r), w.size + Vector2(2*r, 2*r)))
```

**不做这一步，路径会贴着墙走**，RL 一打方向就蹭墙，然后你会误以为是奖励函数的问题。

### 步骤 3：建栅格并标记实心格

```gdscript
grid = AStarGrid2D.new()
grid.region = Rect2i(0, 0, int(arena_size.x / cell_size), int(arena_size.y / cell_size))
grid.cell_size = Vector2(cell_size, cell_size)
grid.diagonal_mode = AStarGrid2D.DIAGONAL_MODE_ONLY_IF_NO_OBSTACLES   # 防止斜穿墙角
grid.update()
for y in range(grid.region.size.y):
    for x in range(grid.region.size.x):
        var p := cell_to_world(Vector2i(x, y))
        for b in inflated:
            if b.has_point(p):
                grid.set_point_solid(Vector2i(x, y), true)
                break
```

**选 cell_size**：你场地 200×200。
- 1.0 m → 4 万格，查询毫秒级，足够；
- 0.5 m → 16 万格，更精细但更重；
- **建议从 1.0 m 开始**，跑通再谈精度。

### 步骤 4：查路径

```gdscript
func query(from_xz: Vector2, to_xz: Vector2) -> PackedVector2Array:
    var a := nearest_free_cell(world_to_cell(from_xz))   # 车可能贴在实心格里！
    var b := nearest_free_cell(world_to_cell(to_xz))     # 乘客也可能站在墙边
    if a.x < 0 or b.x < 0:
        return PackedVector2Array()                      # 无解，调用方要处理
    var ids := grid.get_id_path(a, b)                    # Godot 4.x 的 API
    var pts := PackedVector2Array()
    for id in ids:
        pts.append(cell_to_world(id))
    return pts
```

**`nearest_free_cell()` 必须写**：如果车正好停在实心格里（贴墙、生成点压线），A* 会直接返回空路径，表现为"车突然没有目标"——这个 bug 能烧掉你一天。

### 步骤 5：拉直（string pulling）——把锯齿折线压成 3–5 个路点

A* 的输出是逐个格子的锯齿线，直接喂 RL 会让它学"抖动"。用视线检查把能直达的点合并：

```gdscript
func pull_string(path: PackedVector2Array) -> PackedVector2Array:
    if path.size() <= 2: return path
    var out := PackedVector2Array([path[0]])
    var i := 0
    while i < path.size() - 1:
        var j := path.size() - 1
        while j > i + 1 and not los_clear(path[i], path[j]):
            j -= 1                    # 从最远处往回退，找到第一个能直达的
        out.append(path[j])
        i = j
    return out
```

`los_clear()` 的两种实现：
- **推荐**：用物理引擎射线查询（你已经有一套物理世界）——
  ```gdscript
  func los_clear(a: Vector2, b: Vector2) -> bool:
      var q := PhysicsRayQueryParameters3D.create(
          Vector3(a.x, probe_y, a.y), Vector3(b.x, probe_y, b.y))
      q.collision_mask = wall_mask      # 只打墙！别打到车、乘客、地面
      return space.intersect_ray(q).is_empty()
  ```
- 或者自己写 2D 线段 vs AABB 的 slab 法（10 行，更快，无物理依赖）。

### 步骤 6：重采样成"等间距路点"

拉直后的折线**顶点间距是不均匀的**（拐角处密、直道处稀），这对 RL 很不友好。按固定间距重采样：

```gdscript
func resample(pts: PackedVector2Array, spacing: float) -> PackedVector2Array
# 沿着折线每隔 spacing（建议 6 m）取一个点
```

于是 RL 的输入永远是"前方 6 m、12 m、18 m 的三个点"，形式统一。

## 2. 进阶版本：稀疏路点图（更少节点，路径同样好）

上面是栅格版（4 万个节点）。稀疏版节点只有几十个，A* 更快、图更小，但要多写一点几何。

**节点从哪来（按优先级）**
1. **障碍的凸角点**：每个膨胀后的盒子 4 个角，去掉落在其它盒子内部的；
2. **开阔区域的粗格点**：⚠️ **必须有这一步**。纯角点图在开阔场地上会退化——两辆车都在空地上时，附近没有节点，A* 会绕到墙角的节点再折回来。所以要做**混合图：角点 + 开阔区稀疏格点**；
3. 可选：窄道/路口的补充点（宽度局部极小的位置）。

**边怎么建**
- 暴力两两配对 → 用 `los_clear()` 过滤 → 权重 = 欧氏距离；
- 节点数 40 时是 780 对，一次性烘焙完全没问题；
- 用 `AStar2D`：`add_point(id, pos)` / `connect_points(a, b, true)` / `get_point_path(a, b)`。

**起点和终点不在图里怎么办**
把你当前的起点/终点作为**临时节点**加入图（连到所有可见节点），查询完删除。这是标准做法，别去硬找"最近的节点"——那会造成明显的绕路。

**稀疏版必须做连通性检查**（栅格版天然连通，稀疏版不一定）：
```gdscript
# 从起点 BFS，能到达的节点比例；< 100% 就要补点或补边
```

## 3. 接进 RL（这一步才是你真正的目的）

### 3.1 观测（约 10 维，替换你现在的"目标 6 维"）

| 内容 | 维度 |
|---|---|
| 前方 3 个 lookahead 路点的**车体坐标**相对位置 | 6 |
| 横向偏差（车到路径折线的垂距，归一化） | 1 |
| 航向偏差（车头 vs 路径切线夹角） | 1 |
| 沿路径的投影速度 | 1 |
| 路点进度（剩余路点数 / 总路点数） | 1 |

### 3.2 奖励：势函数从"直线距离"改成"沿路径剩余弧长"

```
现在： Δ ∝ (∥目标 − 上一位置∥ − ∥目标 − 当前位置∥)
改成： Δ ∝ (s_prev − s_now)        # s = 沿路径的剩余弧长
```
投影时**必须把搜索窗口限制在上一帧投影点附近（±10 m）**，否则车一偏离路径，投影点会跳到路径另一端，奖励瞬间爆掉。

### 3.3 重规划策略（**别每帧重算**）

| 触发条件 | 说明 |
|---|---|
| 目标变化 | 接了新乘客、目的地变更 |
| 卡死检测 | N 步内沿路径弧长进度 < 阈值 → 重算 + 触发倒车脱困 |
| 定时 | 每 K 个决策步刷新一次（可选） |
| ❌ 每物理帧 | 不要：目标频繁跳变会让 RL 追逐移动靶 |

**滞回**：新路径与旧路径差异小于阈值时不替换，避免抖动。

## 4. 必须做的单测与可视化（"一窍不通"的人尤其要做）

### 4.1 可视化（**这是你理解自己图的最快方式**）

用 `ImmediateMesh` 或 `Node3D` 画 debug 线：
- 白点 = 节点，灰线 = 边，红/绿线 = 分别表示不可达/可达路径；
- 一个 `debug_draw` 开关，别在正式训练里开着。

**能看见图，你才可能在半小时内找到"为什么车绕远路"。** 不看图硬调，你会浪费几天。

### 4.2 四项单测

| 测试 | 合格标准 |
|---|---|
| 连通性 | 200 组随机自由 (起点, 终点) 全部有解 |
| 路径质量 | 路径长度 / 直线距离 的分布合理；与 0.25 m 细栅格参考比 ≤ 1.05 |
| **净空** | 路径上**每一点**到墙的最小距离 ≥ 车半宽（断言，不是"看着像"） |
| 查询耗时 | 单次查询毫秒数；确认它远小于一个物理帧 |

### 4.3 端到端

接上 RL 后，与"没有引导（纯射线）"做 A/B：成功率、平均到达时间、**卡死率（局部极小次数/回合）**。

## 7. 附：为什么这里不用 RRT？以及四种生成方式对比

### 结论：RRT 在这个问题上比栅格更麻烦，且与"静态图"的架构决定冲突

**RRT 的主场是高维构型空间**（6/7 自由度机械臂、带非完整约束的车辆构型空间）。你的问题是 **2D + 几个凸盒子**——这是栅格/可见性图的**最简单情形**，RRT 在这里买不到任何东西。

| 维度 | 栅格 + A* | RRT / RRT* |
|---|---|---|
| 实现量 | 约 60–120 行，而且**搜索由引擎内置** | 更多：采样循环 + 最近邻 + steer + 目标偏置 + 失败/超时处理 + 平滑 |
| 最优性 | 分辨率完备（1 m 格在本问题里等同精确） | 普通 RRT **不最优**；RRT* 渐近最优但收敛慢 |
| 路径形态 | 锯齿，需拉直 | **也是锯齿，也要拉直**（同一个 `pull_string`） |
| 碰撞检查 | 膨胀 + 建格（一次性） | 每条边都要碰撞检查（等价工作量，甚至更多） |
| 确定性 | 完全确定、可复现 | **随机**：同一 (起点,终点) 两次查询路径不同 |
| 可复用性 | **烘一次、三处共用、可版本化** | 单查询算法，**每次查询重新长树**，不产生可复用结构 |
| 窄道表现 | 只要通道宽度 > cell_size 就一定找到 | 随机采样命中率低（窄通道问题），常需重试 |
| 对 RL 的引导 | 稳定、连续 | **跳变**（你之前被警告的"引导分布漂移"会严重十倍） |

**最关键的一条**：你要的是"静态地图、烘焙一次、只读"，而 **RRT 天生是"每次查询在线规划"**——它不产出静态图，这跟你已经定下的架构（以及"训练/评估/演示同图"的纪律）是矛盾的。

### 但你的直觉对了一半：你要的是 **PRM**，不是 RRT

RRT 和 PRM 共享同一个想法——**随机采样，不画格子**。区别在于：

- **RRT = 单查询**：每次从起点长一棵树，用完就扔；
- **PRM = 多查询**：先采样 N 个自由点，按邻近关系连边并做碰撞过滤，**得到一张图**，之后每次查询都在图上跑 A*。

**PRM 产出的东西就是路点图。** 所以"用随机采样代替画格子"完全可行，而且：

- 实现比栅格**更短**（不需要遍历所有格子标 solid）；
- 它正好就是我之前列的对照基线 **G2（均匀随机采样图）**——**一箭双雕：既简化实现，又变成论文实验的一部分**；
- ⚠️ 但有已知弱点：**窄通道问题**——纯随机采样很少落在窄道里。标准修法是 **obstacle-based sampling**（在障碍边界附近采样），而它的极限就是"采样到障碍角点上"——**这正是可见性图**。所以在你这种"少量凸盒子"的几何下，最佳方案仍然是 **障碍角点 + 开阔区补充点** 的混合图。

### RRT 真正会派上用场的地方（未来，不是现在）

等你要做**带最小转弯半径的窄路口转向 / 三点掉头**时，构型空间是 `(x, z, θ)` 且带非完整约束——那时栅格和可见性图都不适用（可见性图求的是几何最短，不是车能开出来的最短），**RRT\* / Dubins-RRT / 混合 A\* 才有真正的主场**。所以别现在否掉 RRT，只是它解决的不是"静态可走区域寻路"这个问题。

### 如果嫌栅格麻烦，真正省事的入门顺序

1. **手摆节点（30 分钟跑通全链路）**：在场景里拖 20–40 个 `Marker3D` 当节点，加载时一次性做 LOS 检查生成边，用 `AStar2D` 查询。**零算法、零采样、零栅格**。先验证"路径 → lookahead → RL 观测 → 奖励改弧长"这条链路通不通；
2. **再自动化生成**：角点图（最优性最好）或 PRM 随机采样（实现最短），二选一；
3. 最后才考虑"学习式布点"。

**注意：无论走哪条路，膨胀/净空处理、路径拉直、lookahead 重采样这三件事都躲不掉**——它们不是你选栅格带来的麻烦，而是"给车用的路径"本身的要求。RRT 一样要写。

## 8. 常见坑清单（照这个自查）

1. **忘记膨胀障碍** → 路径贴墙 → RL 蹭墙（最常见的误判来源）；
2. **没写 `nearest_free_cell`** → 起点/终点落在实心格 → 返回空路径 → "车突然没目标"；
3. **坐标系搞混** → Godot 3D 水平面是 **XZ**，别把 `(x, y)` 当水平面；
4. **射线过滤没设** → 打到车自己/乘客/地面 → 视线永远不通 → 图连不起来；用 `collision_mask` + `exclude`；
5. **对角穿角** → `diagonal_mode` 要设 `ONLY_IF_NO_OBSTACLES`，否则路径会斜切过墙角；
6. **路点间距不均** → 重采样，别把 A* 原始折线喂网络；
7. **每帧重规划** → 目标跳变，RL 学不会；按事件触发；
8. **投影窗口不限** → 偏离路径后奖励爆掉；
9. **训练/评估用了不同的图** → 把烘好的图**导出为资源并版本化**，三处共用；
10. **在 GDScript 里手写四叉树** → 不要；你已经有了 AStarGrid2D。

## 9. 建议的文件与推进顺序

```
vehicle/AI/Nav/ArenaNavGraph.gd     # 烘焙 + 查询 + 拉直 + 重采样（一个脚本够）
vehicle/AI/Nav/NavDebugDraw.gd      # 可视化（先写这个）
```

**推进顺序（每一步都能单独验证）**
1. 抽墙 + 膨胀 + 建栅格 → 打开可视化，**肉眼确认墙是实心的、通道是通的**；
2. 查询 + 拉直 + 重采样 → 在空场地/墙场地各画几条路径，肉眼对比是否合理；
3. 四项单测（连通性/质量/净空/耗时）；
4. 接观测（10 维）+ 势函数改弧长 → 重训单车，与"纯射线"版本 A/B；
5. 卡死检测 + 倒车脱困；
6. 只有在 1–5 都通过后，才考虑"稀疏图"或"学习式布点"。
